================================================================================
PROJECT REQUIREMENTS & STEP-BY-STEP EXECUTION PLAN
================================================================================
Module: Deep Learning in the Clinic: From Algorithms to Virtual Cells
Project: Comparative Benchmarking of Standard RAG vs. Cross-Encoder & GAR Architectures
Dataset: PubMedQA

--------------------------------------------------------------------------------
1. PROJECT REQUIREMENTS (CONTENT BREAKDOWN)
--------------------------------------------------------------------------------

A. DATASET & CORPUS
- Dataset: PubMedQA (Biomedical Question Answering)
- Passages: Extract abstracts into passage chunks to build the knowledge corpus.
- QA Triplets: Use integrated Question-Context-Answer pairs for evaluation.

B. MODEL SELECTION & TECHNICAL STACK
- Initial Retrievers:
  * BM25s (Lexical baseline via bm25s Python library)
  * Dense Retriever (lightonai/Reason-ModernColBERT or qwen3-embed-0.6b)
- Corpus-Graph Models (for GAR):
  * BM25s, lightonai/Reason-ModernColBERT, or qwen3-embed-0.6b to compute document similarity edges.
- Re-Ranker:
  * monoT5-base or HuggingFace Cross-Encoder models.
- End-to-End Generator (DO LAST):
  * Small Biomedical/General LLM (e.g. Llama-3B-Instruct).

C. EVALUATION METRICS
- Retrieval Metrics (Primary Benchmarking):
  * pytrec_eval library (nDCG@10, Recall@10, Recall@100, Recall@1000)
- End-to-End Generation Metrics (Secondary, Executed Last):
  * RAGAS framework (Faithfulness, Answer Relevance)

D. COMPUTE & HARDWARE
- Local Hardware: NVIDIA RTX 5060 (16 GB VRAM)
- Cluster Resource: KISSKI GPU Platform (https://kisski.gwdg.de/en/leistungen/2-01-01_trainingsplattform/)

--------------------------------------------------------------------------------
2. STEP-BY-STEP EXECUTION PLAN
--------------------------------------------------------------------------------

PHASE 1: ENVIRONMENT & COMPUTE SETUP
- Apply for KISSKI GPU cluster resources (https://kisski.gwdg.de/en/leistungen/2-01-01_trainingsplattform/).
- Define project requirements and documentation files (.txt / .md).

PHASE 2: CORPUS PREPARATION & CORPUS-GRAPH CONSTRUCTION
- Download and parse PubMedQA abstracts into unstructured passage corpus.
- Pre-compute similarity edges between document passages using BM25s / ModernColBERT / Qwen3-Embed embeddings to build the Corpus Graph.

PHASE 3: INITIAL RETRIEVAL BASELINE (STAGE 1)
- Build lexical retrieval index using BM25s.
- Build dense retrieval index.
- Evaluate retrieval quality using pytrec_eval on nDCG@10, Recall@10, Recall@100, Recall@1000.

PHASE 4: STATIC RE-RANKING & GAR INTEGRATION (STAGES 2 & 3)
- Implement Static Re-Ranking (Top-N+M candidates scored via monoT5-base / Cross-Encoder).
- Implement Graph-based Adaptive Re-ranking (GAR): Dynamic candidate expansion using multi-hop neighbors in the pre-computed Corpus Graph, followed by adaptive re-scoring.

PHASE 5: QUANTITATIVE RETRIEVAL BENCHMARKING
- Compare 3 pipeline stages: Standard Retrieval vs. Static Re-Ranking vs. Graph-Adaptive Re-Ranking (GAR).
- Perform ablation studies on corpus graph density, model selection, and recall gains.

PHASE 6: END-TO-END GENERATION & RAGAS ANALYSIS (DO LAST)
- Feed Top-N contexts into Llama-3B-Instruct to generate final medical answers.
- Evaluate end-to-end quality using RAGAS for Faithfulness and Answer Relevance.

PHASE 7: FINAL REPORT & PRESENTATION
- Plot retrieval precision and recall trade-offs.
- Finalize slides and final project report for the module directors.
